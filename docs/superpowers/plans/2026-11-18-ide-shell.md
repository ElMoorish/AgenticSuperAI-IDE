# IDE Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Windows desktop IDE shell (Tauri v2 + Monaco) that hosts the existing `agent-core` as an ACP editor, with safe file access, diff approval, terminals, model/GPU status and crash recovery.

**Architecture:** Three processes: React/Monaco webview, a Rust host (`crates/ide-host`, Tauri-free, plus a thin `apps/shell` Tauri app), and `agent-core` as a sidecar over line-delimited JSON-RPC on stdio. The webview only sees narrow typed commands and batched `Channel` streams.

**Tech Stack:** Rust (tokio, serde, notify, portable-pty, sha2), Tauri v2, React + TypeScript + Vite, Zustand, Monaco (ESM, Vite `?worker`), xterm.js, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-18-ide-shell-design.md`. UI reference: `.superpowers/brainstorm/14279-1795017487/content/workbench.html`.

## Global Constraints

- Windows 10 is the only tested platform; WebView2 runtime required, installer bootstraps it.
- The webview gets no shell-spawn permission (no `shell:allow-execute`); the agent is spawned from Rust with `tokio::process`. CSP strict, no remote content, fonts bundled.
- Every path (UI commands and agent requests) is canonicalised and must stay under the opened workspace root.
- Streams to the webview are coalesced in ~16 ms batches and size-capped; terminal/tool output uses bounded ring buffers.
- Saves and agent writes are atomic (temp file + rename) and refused on disk-conflict.
- Monaco workers load through Vite `?worker` imports with `MonacoEnvironment.getWorker`; only needed language workers.
- Idle memory target under 300 MB for shell + host (excluding the model).
- ACP subset: `initialize`, `session/new`, `session/prompt`, `session/cancel`, `session/update` (`agent_message_chunk`, `tool_call`, `tool_call_update`, plus `usage`), `fs/read_text_file`, `fs/write_text_file`, `session/request_permission`, `terminal/create|wait_for_exit|output|release`.
- Plan-level numbers (my calls, adjust freely): Monaco open-size cap 5 MB; diff render cap 2,000 changed lines; agent terminal ring buffer 256 KB; restart backoff 0.5 s, 1 s, 2 s, 4 s then stop after 5 crashes in 60 s.
- Existing tests must keep passing: `cargo test`, `python -I scripts/smoke.py`.

## Review Focus

1. A path that escapes the workspace via `..`, an absolute path elsewhere, or a junction/symlink: refused with a clear error. (Task 2)
2. The file changed on disk after it was loaded and the user accepts an agent edit or presses save: conflict prompt, no silent overwrite. (Task 4)
3. CRLF files, UTF-8 BOM and paths with spaces (the repo path itself has spaces): reads, diffs and saves keep line endings and encoding. (Task 4)
4. The agent prints a 100k-line tool result or proposes a huge diff: UI stays responsive, output is truncated with a notice. (Tasks 5, 11)
5. The agent process dies, or the model server is down, while an approval is pending or a turn is running: visible banner, pending approval cleared, turn ends, restart works. (Tasks 3, 14)
